# Inventory correspondence: separate records, reviewed navigation

Design contract for the inventory workstream. Read with the inventory-reconciliation research decision. Commit this contract before implementing the ledger or changing collection presentation.

The directory can propose a map record, and the publisher view can show nearby outlines, but neither provides a persistent reviewed correspondence with endpoint-version history. This blocks a coherent source-to-facility journey and gives repeated candidate navigation the appearance of completed identity work.

Keep research projects, community features, operator codes and publisher locations as independently versioned records. Introduce a link publication with typed endpoints, an exact relationship scope, cited review evidence and append-only decisions. Never replace a publisher pin with an outline center, attach project capacity to a map feature, or call mixed record counts unique facilities.

## Link and review boundary

Each endpoint stores collection ID, native record ID, full-publication hash and canonical record hash. OSM keys retain element type, ID and native version. The candidate stores relationship kind, scope, evidence source/version or original URL, exact locator, proposed basis and explicit unresolved facts. Initial kinds are named-facility correspondence, campus membership and adjacency. Their meanings are distinct; none certifies geometry, ownership, service, current operation or IT allocation.

A proposal is immutable and unaccepted. A named reviewer appends an accepted/rejected/superseded decision with reason and UTC review time. Acceptance checks the expected link-publication head and current endpoint content. A changed endpoint produces “Source changed — review needed”; old evidence and decisions remain inspectable, while stale correspondences leave the effective accepted view. An unrelated row changing the publication can update source context without pretending the linked record changed. No transitive equivalence or automatic nearest-object acceptance.

The four legacy Equinix corroborations retain their original dates, source text and uncertainty. Import them as explicitly marked migration candidates; they have no fabricated named actor or certified geometry. Re-review their exact code/address evidence before a new effective accepted decision. Rejected identity candidates remain visible in history with the conflict, not silently removed from audit exports.

## User journey and composition

From a selected source record, the adjacent rail identifies the collection role, native code/ID, source vintage and original coordinate basis. A second group offers three distinct states: Reviewed correspondence, Proposed identity candidate, Nearby source feature. Proposed/nearby actions use restrained styling; a mint accepted state requires a current effective review.

A correspondence card names both records, relationship scope, dated review and the evidence. Inspecting the other record preserves the prior camera, selection and source-return route. Both original coordinate roles remain visible. A compound publisher entry opens its native compound identity; separate buildings are not invented from tokens in its title. Multiple candidates remain selectable and counted. A preview limited to four nearby outlines says it is a preview rather than claiming an exhaustive match set.

A review drawer puts the compared native names, complete codes, addresses, pins and evidence beside the proposed scope. Conflicting addresses and changed source versions appear next to the decision controls. A pending source or unavailable original leaves the accepted older statement visible as dated history; it does not silently renew it. The source-health queue links to the impacted correspondence review.

The directory keeps its separate collection totals, captures and filters. A mixed discovery result says “records across collections” and groups by role. Research MW totals continue to come only from the accepted capacity publication. Source correspondence gives navigation and explicit identity scope; it never creates an extra capacity project.

## Read and write contracts

A read view returns the selected native record, current effective correspondences, proposals, conflict/review state and history. Its offline projection embeds accepted/pending states with endpoint and publication versions; it never presents the bundled projection as a live review queue.

Candidate creation validates endpoint membership and hashes against staged or accepted source publications. Decision writes require a named reviewer/reason, expected link head and endpoint leases. The transaction appends history and advances the separate link publication atomically. It does not modify the source record, source snapshot or capacity ledger. Stale decisions fail with enough context to reopen the current comparison. Export preserves every original source envelope and independently exports link/review history; mixed rights are not relabeled with one source's license.
